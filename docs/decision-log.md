# Decision Log

> Single source of truth for design rationale on the Haze (`libhaze`) initiative,
> maintained per **Rule 1 (Explainability)** of the Agent Action Plan.

## How this log works

This document records the rationale behind every non-trivial implementation
decision on the Haze initiative. Per Rule 1, rationale lives **here and only
here** — it is deliberately kept out of code comments so that code stays
declarative while the reasoning, alternatives, and risks live in one auditable
place.

- **Scope.** Every non-trivial decision, and every deviation from a literal
  reading of the requirements, has a row in the [decision table](#2-decision-table).
  Unexplained deviations are treated as defects.
- **Traceability.** Because this initiative includes migrations and refactors
  (graph capture on top of the epoch subsystem; README examples mirrored into
  `examples/`), the log also carries a bidirectional
  [traceability matrix](#3-traceability-matrix) with 100% coverage.
- **Organization.** The log is append-oriented and organized by work item /
  priority tier (`P1a`, `P1b`, `P2a` … and Rules 1–3). Each pull request cites
  the decision IDs it implements in its description.
- **Stable IDs.** Decision IDs (`D-01`, `D-02`, …) never change or get
  renumbered; new decisions take the next free ID.

## 4. Deviations and assumptions

### 4.1 Deviations

Each deviation from a literal reading of the requirements is logged here and
linked to its decision-table entry, per Rule 1.

- **Single integrated branch supersedes the per-work-item PR directive.** The
  brief calls for "separate PRs per work item (or per priority tier)"; the
  remediation instead lands the entire initiative — runtime, tests, benchmarks,
  observability, and docs — as one coherent branch so every review finding is
  resolved and verified together against a single tree. Consequently, artifacts
  the earlier framing described as "deferred to a later PR" (the graph/peer/counter
  runtime, `test/test_allocator_limits.cpp`) are delivered now, and only physical
  multi-chip peer-access validation remains marked deferred. See [D-22](#d-22).
- **Observability reinterpreted for a library context.** The rule's
  network-service vocabulary (metrics endpoint, distributed tracing, health
  checks) is mapped to library equivalents rather than implemented literally.
  See [D-04](#d-04).
- **Executive summary embeds its theme inline.** The canonical
  `blitzy-deck/references/blitzy-reveal-theme.css` is absent from the checkout,
  so the deck is delivered as a single self-contained HTML file with the theme
  embedded; the canonical file's contents are not fabricated. See [D-12](#d-12).
- **Coverage gate deferred behind backfill/hardening.** Rather than enabling the
  80% gate immediately, it is sequenced after P2d/P2e raise coverage — a
  deviation from a literal "add the gate now" reading, justified as a logical
  dependency. See [D-06](#d-06).
- **The C1 finding's literal "revert the registrations" suggestion is declined
  on AAP-precedence grounds.** C1 suggests moving the `src/core/{graph,metrics}.cpp`
  and new-test registrations out of this change into a separate final-integration
  pair. AAP §0.6.1 lists `CMakeLists.txt` as an in-scope UPDATE that must "register
  all new test files," and §0.6.5 states every new `test/*.cpp` must be added to
  `add_executable(haze_tests ...)` "or it will not be compiled or run." Because the
  AAP overrides a finding's suggested resolution, the registrations are kept — each
  source registered exactly once (verified) — and the actionable half of C1
  (exactly-once, no duplicate registration) is satisfied. See [D-26](#d-26).
- **The benchmark regression gate hard-fails the build but only beyond a
  deliberately wide tolerance band.** A literal reading of P1b ("flag regressions
  against a baseline") could be taken to mean failing on any measured slowdown;
  because CI shares runners with variable performance, the wired
  `scripts/bench_compare.py` gate instead fails only when a benchmark is
  missing/renamed/errored/empty or its per-benchmark median regresses beyond a
  wide threshold, using recorded host metadata, so it fires on real regressions
  rather than on noise. An earlier interim framing described this check as
  advisory-only ([D-30](#d-30)); it was hardened into the strict wired gate in
  [D-45](#d-45), and that wording was reconciled across this log and the deck in
  [D-66](#d-66). See [D-30](#d-30), [D-45](#d-45), [D-66](#d-66).
- **`examples/` is kept outside the `clang-format` enforcement scope.** A literal
  "keep clang-format clean" reading would add `examples/` to the formatted set,
  but the example sources are generated mirrors of the authoritative README fenced
  blocks and must match the README's presentation formatting and the docs-as-tests
  extraction; enforcing repository `clang-format` on them would fight that. They
  are instead kept format-idempotent by construction and proven equivalent to the
  README by `scripts/test_readme_examples.sh`. See [D-31](#d-31).
- **"Opens offline" claim corrected; CDN load made resilient.** The traceability
  matrix previously described the deck as opening offline, but it references
  pinned CDN assets (reveal.js, Lucide, Mermaid) and therefore requires network
  for full fidelity. The claim is corrected to state the deck is a single
  self-contained file that requires network for its pinned CDN assets, and
  reveal.js initialization is decoupled from the Mermaid CDN so a diagram-CDN
  outage degrades to captioned fallbacks rather than blanking the deck. See
  [D-13](#d-13).
- **Diagnostic lines are composed then emitted with one `std::fwrite`.** Rather
  than performing several independent per-field writes (which would interleave
  under concurrent multi-threaded logging), each record is composed into a
  single `std::string` and written with one `std::fwrite(..., stderr)` to
  satisfy the line-integrity / concurrency-isolation property of Rule 2. Field
  contents are neutralized deterministically by `append_escaped` (newlines,
  control bytes, and non-ASCII rendered as `\xNN`), so framing integrity does
  not depend on a timing-sensitive thread race. On any formatting/write failure
  the `catch (...)` handler emits a fixed, allocation-free generic dropped-record
  notice via `std::fputs` — not a re-emission of the record — preserving
  `noexcept`. See [D-16](#d-16).
- **Peer access is simulator-only and validates device ordinals.** Physical
  multi-chip peer transfer needs hardware absent from CI, so only the
  simulator-representable query -> enable -> copy path is implemented, and the
  peer entry points validate device ordinals (rejecting negative and
  out-of-range indices) rather than accepting them unchecked as the superseded
  comment implied. Hardware-only assertions sit behind a hidden tag and the
  multi-chip step is flagged as human follow-up. See [D-09](#d-09).
- **`test/test_config_errors.cpp` exercises the real `set_modulus` contract, not a
  nonexistent index cap.** A literal reading of the review suggested asserting
  that index 64 is rejected after populating 0–63; an empirical probe proved
  `Config::set_modulus` has no hard 64-index cap (writing 64 and 65 succeeds
  after a contiguous fill), so the test exercises the actual sparse-write /
  contiguity / post-configure-immutability contract instead. See [D-21](#d-21).
- **`test/test_allocator_limits.cpp` is delivered.** With the single-pass
  integrated delivery (see [D-22](#d-22)) there is no separate later PR to defer
  to, so the allocator pool-exhaustion / zero / oversized boundary TU is present
  in the tree, registered exactly once in `add_executable(haze_tests ...)`, and
  runs in the default suite. The earlier "deferred" rationale is withdrawn because
  it is no longer true against the checkout. See [D-17](#d-17).
- **The lock-order concurrency test is scoped to independent per-thread
  allocation churn.** A literal "epoch/allocator lock-order under concurrent op
  recording" test is not expressible because record-and-replay is single-writer,
  so the delivered `[.][concurrency]` test in `test/test_error_paths.cpp`
  exercises the allocator lock under eight-thread contention while the nested
  epoch-path ordering is documented as deferred. See [D-18](#d-18).
- **Concurrency stress is co-located with each surface it defends.** Beyond the
  allocator lock-order case, the delivered `[.][concurrency]` suite now covers
  peer-call races (`test/test_peer_access.cpp`), graph launch/update/destroy
  lifetime races (`test/test_error_paths.cpp`), and counter snapshot/reset races
  (`test/test_performance_counters.cpp`); all were run under `HAZE_TSAN=ON` with
  zero data races. The counter case is the single documented exception that
  reaches the internal `haze::metrics()` aggregator, because a public
  `hazeDeviceReset` tears down the allocator and cannot safely race active device
  work. See [D-32](#d-32).
- **The no-exception-across-the-ABI proof uses a fork death-test.** Because a
  throw escaping a `noexcept` function terminates the process before any
  in-process matcher can observe it, `REQUIRE_NOTHROW` cannot prove the property;
  a fork-subprocess death-test is used instead. See [D-20](#d-20).
- **White-box test access is used only where a public getter does not exist.**
  The public C ABI intentionally exposes no state getters, so a few tests reach
  internal `haze::` symbols (for example `haze::to_public_error` for the ES2
  mapping table, and the `AllocatorTestAccess` helper already used by the
  baseline `test/test_memory.cpp` for MRP-allocation negatives). This is a
  deliberate white-box choice for assertions that have no black-box surface;
  MRP-allocation negative cases remain owned by `test/test_memory.cpp` and are
  not duplicated in the new introspection tests.
- **Deck Mermaid pin bumped from the Rule 3 literal 11.4.0 to the patched
  11.15.0 on security grounds.** Rule 3 pins Mermaid at 11.4.0, but that release
  is in the affected range of CVE-2026-41149 (classDef HTML/DOM injection, fixed
  in 11.15.0) and the earlier CVE-2025-54880 / CVE-2025-54881 (fixed in 11.10.0),
  and the QA SEC-05 finding treats a known-vulnerable dependency with an available
  fix as blocking. The pin is bumped to 11.15.0 — the smallest single version that
  closes all three CVEs — while every other Rule 3 constraint (exact-version pin,
  single self-contained file, 16 slides, the `hash`/`transition`/1920x1080 config)
  is preserved, and the [D-33](#d-33) sandbox posture plus the [D-46](#d-46) iframe
  hardening are retained as defense-in-depth on top of the patched version. This
  security-driven change is permitted under Rule 1 as an explicitly logged
  deviation and supersedes the "freeze at 11.4.0, upgrading not permitted"
  conclusion recorded in [D-33](#d-33)/[D-13](#d-13). The companion CDN
  supply-chain hardening (a Content-Security-Policy meta and `crossorigin` on the
  four tag-based loads, with SRI intentionally omitted and that omission
  documented) is additive and does not deviate from any Rule 3 requirement. See
  [D-51](#d-51) and [D-52](#d-52).
- **QA SEC-04's suggested output-permission fix is declined on AAP-precedence
  grounds.** The finding suggests tightening the world-readable 0644 permissions
  on the vendored FHETCH simulator's `.ct`/`.template` scratch artifacts, but its
  root cause is in `vendor/niobium-fhetch/` `auto_facade.cpp`, which AAP section
  0.3.2 places out of scope (the vendored-dependency and `replay_bridge/`
  OpenFHE-isolation boundary, plus "refactoring unrelated to the enumerated work
  items"). Because the AAP overrides a finding's advisory suggested fix, the
  in-tree change is declined and the item is routed to explicit human follow-up
  upstream in niobium-fhetch; libhaze itself creates none of these files, so there
  is no in-scope seam at which to interpose. See [D-53](#d-53).
- **Small-viewport deck responsiveness and the `<main>` landmark are hardened
  beyond the literal Rule 3 constraints.** Rule 3 binds the executive deck to a
  fixed 1920&times;1080 reveal.js canvas and is silent on &le;768px reflow and on
  ARIA landmarks; the deck already satisfied that literal contract at every
  desktop breakpoint. Rather than leave the two QA-observed small-viewport
  limitations undocumented (an undocumented limitation is itself a Rule 1 defect),
  the `@media (max-width: 768px)` reflow was extended so the coverage/progress
  charts, the workstreams table, and the roadmap timeline scale or stack into one
  column instead of clipping (QA P6-UI-04), and the whole deck was wrapped in a
  single top-level `<main>` landmark so mobile Lighthouse accessibility reaches 100
  (QA P6-UI-05). The P6-UI-04 rules are confined to the sub-768px media query; the
  P6-UI-05 `<main>` wrapper is made layout-transparent (`height:100%`) so it adds
  the landmark without altering box geometry (a bare block wrapper would collapse
  reveal.js's percentage-height chain &mdash; see [D-69](#d-69)). The mandated
  1920&times;1080 rendering was re-verified pristine after both changes (desktop
  Lighthouse accessibility 100 with no height collapse). See [D-68](#d-68), [D-69](#d-69).



### 4.2 Assumptions

- **Toolchain availability.** Google Benchmark 1.9.5 resolves from the pinned
  nixpkgs as `gbenchmark`, and `llvm-cov` / `llvm-profdata` are provided by the
  Clang 19 toolchain with no additional runtime dependency. See [D-01](#d-01),
  [D-02](#d-02).
- **Integrated tree (assumption discharged).** The files referenced here — for
  example `../src/core/graph.hpp` and `./observability/README.md` — are all
  present in the integrated single-pass branch (see [D-22](#d-22)), so the
  relative links in this log resolve against the actual tree rather than assuming
  future sibling PRs. This assumption is therefore discharged, not pending.
- **Pointer stability.** `DevAddr` operands remain stable across graph replays;
  this is the correctness invariant underpinning graph capture. See
  [D-03](#d-03).
- **Concurrent-process isolation.** Concurrent processes that record and replay
  must each set a distinct `hazeSetProgramDirectory` before their first compute
  call; the shared base recording directory is otherwise a cross-process
  data-mixing hazard, and corrupt or partial on-disk artifacts always surface as
  `HAZE_ERROR_INTERNAL` rather than a C++ exception crossing the `noexcept` C
  ABI. See [D-37](#d-37).
- **Export contract.** The `haze*` version-script wildcard remains the sole
  export contract, so filling the already-exported stubs needs no change to
  `linker/haze_exports.{map,sym}`. See [D-11](#d-11).
